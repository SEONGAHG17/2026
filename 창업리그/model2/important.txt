[ 모델 2 실행 전 필수 체크 리스트 3가지 ]
1) 모델 1의 결과물(.bt)
	모델 2는 모델 인풋으로 concert_stage.bt 지도를 반드시 필요로 합니다.
	런치 파일 안에서 지정한 경로(~/concert_model1/maps/concert_stage.bt)에 
	실제 .bt 파일이 만들어져 있어야 OctoMap 서버가 지도를 정상적으로 로드할 수 있습니다.

2) Gazebo 시뮬레이터와 드론 센서가 켜져 있는가?
	모델 2가 실행되려면 백그라운드에서 Gazebo 시뮬레이터가 켜져 있고, 그 안에 3D 라이다가 장착된 드론이 스폰되어 있어야 합니다.
	드론이 실시간으로 라이다 스캔 데이터와 위치 정보(TF, Odometry)를 ROS 2 토픽으로 뿜어내고 있어야 
	Nav2와 위치 추정 엔진이 이 데이터를 받아 연산할 수 있습니다.

3) ROS2 package build
	코드를 작성한 뒤에는 터미널에서 작업 공간(Workspace) 최상단으로 이동해 패키지를 빌드하고 환경을 불러오는 과정을 거쳐야 
	ROS 2가 새 패키지를 인식합니다.

	colcon build --packages-select concert_model2
	source install/setup.bash


[ 모든 준비가 되었다면 ! ]
ros2 launch concert_model2 model2_nav_launch.py

	이 명령어를 치면 OctoMap 서버가 .bt 지도를 띄우고, Nav2 제어 스택이 활성화됩니다. 
	이후 RViz2 화면이 함께 뜨면 마우스로 드론의 목표 위치(2D Goal Pose)를 찍어주어 드론이 자율주행하며 
	목표 지점으로 찾아가는 것을 눈으로 직접 확인할 수 있습니다!


[ 현재 모델의 경우 ]
현재 기체에 온보딩하지 않고, 테스트 형식으로서 실제 하드웨어 적용 시 변경해야할 부분이 존재한다.

시뮬레이션 모델
- 실행 하드웨어 : 개발용 고성능 PC 또는 노트북 환경에서 Gazebo 시뮬레이터와 ROS 2 노드들을 함께 구동합니다.
- 센서 데이터 소스 : Gazebo 가상 플러그인이 생성하는 가상 토픽(예: /lidar/points)을 입력받습니다.
- 모터 제어 통신 : Gazebo 물리 엔진 플러그인을 통하여 가상 드론의 속도 명령(geometry_msgs/Twist)을 직접 처리합니다.
- 시간 동기화 설정 : 가상 시간 동기화 설정(use_sim_time: true)을 활성화하여 시뮬레이터 클럭에 맞춥니다.

실제 온보드 모델
- 실행 하드웨어 : 드론 기체 하단에 탑재된 소형 컴패니언 컴퓨터(예: 라즈베리 파이 4B 또는 Jetson 시리즈) 환경에서 직접 구동됩니다.
- 센서 데이터 소스 : 실제 하드웨어 센서의 공식 ROS 2 드라이버(예: Livox, Velodyne 드라이버 등)를 통해 실시간 점군 데이터를 입력받습니다.
- 모터 제어 통신 : 비행 제어기(Pixhawk 등)와 연동되는 MAVROS 또는 Micro-XRCE-DDS 통신 브릿지를 거쳐 실제 모터 ESC를 제어합니다.
- 시간 동기화 설정 : 시스템 실시간 클럭(use_sim_time: false)을 사용하며, 실제 기체 무게와 환경에 맞춰 제어 파라미터를 튜닝합니다.


[ 기체 내 탑제 시 변경해야할 부분 ]
1. 하드웨어 장착 및 컴퓨팅 환경 이전
어떻게 바꾸나: 
	개발용 PC에서 실행되던 모든 ROS 2 노드들을 드론 기체 하단에 장착된 컴패니언 컴퓨터(예: 라즈베리 파이 4B, NVIDIA Jetson 등) 내부의 
	리눅스(Ubuntu/ROS 2) 환경으로 이동시킵니다.
조치 사항: 
	컴패니언 컴퓨터에 ROS 2 작업 공간(Workspace)을 복사하고, 동일하게 colcon build를 수행해 기체 스스로 상황을 연산할 수 있도록 세팅합니다.

2. 센서 데이터 입력 소스 교체 (가상 토픽 ➔ 실제 드라이버)
어떻게 바꾸나: 
	Gazebo가 만들어주던 가상 라이다 토픽(/lidar/points)을 실제 기체에 부착된 물리적 센서의 공식 ROS 2 드라이버로 대체합니다.
조치 사항: 
	예를 들어 라이더 센서로 Livox나 Velodyne 등을 사용한다면, 해당 센서의 공식 드라이버 패키지를 온보드 컴퓨터에 설치하고, 
	런치 파일 내에서 구독하는 토픽 이름을 실제 하드웨어 토픽 이름(예: /livox/lidar)으로 변경합니다.

3. 모터 제어 및 비행 제어기 통신 브릿지 구축 (Gazebo ➔ MAVROS / Micro-DDS)
어떻게 바꾸나: 
	Nav2가 내뱉는 주행 명령(geometry_msgs/Twist)이 가상 물리 엔진이 아니라 실제 비행 제어기(Pixhawk 등)로 전달되도록 통신 브릿지를 연결합니다.
조치 사항: 
	컴패니언 컴퓨터와 비행 제어기 사이를 UART 또는 USB 통신으로 연결한 뒤, 
	ROS 2와 비행 제어기를 이어주는 MAVROS 또는 Micro-XRCE-DDS 미들웨어 노드를 실행 런치 파일에 추가합니다. 
	이를 통해 Nav2의 제어 명령이 비행 제어기를 거쳐 실제 모터 ESC로 들어가게 됩니다.

4. 파라미터 및 시스템 클럭 설정 수정
어떻게 바꾸나: 
	시뮬레이션용 시간 및 가속도 설정을 실제 물리 환경에 맞게 재조정합니다.
조치 사항:
	모든 설정 파일(.yaml)에 있던 use_sim_time: true를 false로 변경하여 시스템의 실시간 클럭을 따르게 합니다.
	실제 드론의 무게, 배터리 소모에 따른 응답 지연, 프로퍼렐 바람 등을 고려하여 Nav2의 가속도(acc_lim_x)와 최대 속도(max_vel_x) 파라미터를 
	현장 테스트에 맞춰 미세 튜닝합니다.
